# Насосолинго — бэкенд (MVP)

FastAPI + PostgreSQL + Redis. Два модуля:

- **auth** — регистрация и вход по e-mail и паролю (Argon2id, JWT, ротация refresh-токенов,
  защита от подбора пароля, сброс пароля по ссылке).
- **game** — игровое ядро: уроки как данные (JSON), прогресс, опыт, уровни, жизни, поток,
  офлайн-синхронизация.

## Запуск в один клик (Windows)

В корне проекта лежат `start.bat` и `stop.bat` — двойной клик по `start.bat`
поднимет базу, проверит окружение, запустит сервер и откроет браузер.
`stop.bat` останавливает базу.

## Запуск вручную

```bash
# 1. Поднять Postgres + Redis
docker compose up -d

# 2. Окружение (Windows: .venv\Scripts\python)
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env

# 3. Таблицы
.venv/bin/python -m alembic upgrade head

# 4. Загрузить контент уроков
.venv/bin/python seed.py

# 5. Аккаунт для разработки (admin / 12345) — только при APP_ENV=dev
.venv/bin/python seed_dev.py

# 6. Запуск (--host 0.0.0.0 нужен, чтобы открыть с телефона)
.venv/bin/python -m uvicorn app.main:app --reload --host 0.0.0.0
```

Приложение: **http://localhost:8000/app**
С телефона в той же Wi-Fi сети: `http://<IP-компьютера>:8000/app`

Swagger: http://localhost:8000/docs

## Тесты

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

95 тестов, БД не нужна: тесты поднимают приложение на SQLite в памяти и подставляют
фейковый Redis. Логика при этом настоящая.

## Свои иконки и картинки

Всё лежит в `web/img/` и раздаётся по `/static/img/...`. Подробности — в `web/img/README.md`.

- **Иконка приложения:** заменить `web/img/icons/app-icon-180.png` и `app-icon-512.png`.
- **Иконки интерфейса:** 24 SVG-иконки в `web/img/icons/`. Каталог с превью —
  на `/icons`. Меняются через блок `const ICONS` в начале `web/index.html`;
  можно подставить свой файл или вернуть эмодзи. Перегенерация набора —
  `python tools/make_icons.py`.
- **Картинки в уроках:** у любого вопроса поля `image`, `image_alt`, `image_caption`.
  Файл кладётся в `web/img/`, в `image` пишется короткое имя.

## Клиент

Веб-клиент лежит в `web/index.html` и раздаётся тем же сервером по адресу `/app`.
Один файл, без сборки. Умеет: вход, карту-скважину, все четыре типа заданий
(`mc`, `tap`, `slider`, `match`), отправку результата с ключом идемпотентности,
автообновление токена. Открывается в Safari на iPhone и добавляется на домашний экран.

## API

### auth
| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/auth/register` | Регистрация, сразу выдаёт токены |
| POST | `/api/v1/auth/login` | Вход по e-mail **или** короткому логину |
| POST | `/api/v1/auth/refresh` | Обновить access по refresh (с ротацией) |
| POST | `/api/v1/auth/logout` | Отозвать сессию |
| POST | `/api/v1/auth/password/reset-request` | Запрос сброса (ссылка — в логи) |
| POST | `/api/v1/auth/password/reset-confirm` | Смена пароля по токену |
| GET | `/api/v1/auth/verify-email` | Подтверждение e-mail |
| GET | `/api/v1/auth/me` | Профиль + состояние |
| GET | `/api/v1/auth/me/export` | Выгрузка всех своих данных (152-ФЗ) |
| DELETE | `/api/v1/auth/me` | Удаление аккаунта (пароль + слово «УДАЛИТЬ») |

### game
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/v1/game/state` | Опыт, уровень, жизни, поток |
| GET | `/api/v1/game/courses` | Дерево курсов и уроков со статусами — карта пути |
| GET | `/api/v1/game/lessons/{id}` | Контент урока (JSON) для офлайн-кэша |
| POST | `/api/v1/game/lessons/{id}/complete` | Завершение урока (идемпотентно) |
| POST | `/api/v1/game/sync` | Пакетная отправка офлайн-очереди |
| GET | `/api/v1/game/review` | Вопросы, требующие повторения |
| POST | `/api/v1/game/review/complete` | Завершение разбора ошибок |
| PUT | `/api/v1/game/daily-goal` | Изменить дневную цель |

Все игровые эндпоинты требуют заголовок `Authorization: Bearer <access_token>`.

## Вход

Тело запроса `/auth/login`:

```json
{ "login": "admin", "password": "12345" }
```

Поле `login` принимает и короткий логин, и e-mail. Старое имя поля `email`
тоже работает — для совместимости.

**Dev-аккаунт `admin` / `12345`** создаётся скриптом `seed_dev.py`. Скрипт
отказывается работать, если `APP_ENV` не равен `dev`: пароль короче политики
(10 символов) и создаётся в обход проверок, поэтому такому аккаунту нельзя
оказаться на боевом сервере. Обычная регистрация слабые пароли по-прежнему
не принимает.

## Ключевые принципы

**Контент — это данные.** Уроки лежат в базе как JSON (`lessons.content`), клиент —
универсальный движок, умеющий рендерить девять типов заданий: `mc`, `odd`, `order`, `number`, `hotspots`, `tap`,
`slider`, `match`, `sound` (аудио + выбор). Новый урок = запись в базе,
БЕЗ релиза приложения. Полное руководство по контенту — `docs/content-guide.md`.

**Идемпотентность.** Клиент присылает `client_event_id` с каждым результатом урока.
Повторная отправка (связь моргнула, очередь ушла дважды) не начислит опыт второй раз.
Это то, что делает офлайн-режим безопасным.

**Опыт считает сервер.** Клиент присылает «сколько верных из скольких», а формулу
применяет сервер — клиент не может объявить себе любое число.

**Жизни считаются на лету.** В базе хранится только момент последнего изменения;
регенерация вычисляется по серверному времени, остаток не теряется.

**Поток — по местной дате игрока** (`users.timezone`), а не по UTC.

**Разбор ошибок.** Клиент присылает результат по каждому вопросу (`answers`),
сервер помнит их в `question_attempts`. Вопрос, отвеченный неверно, попадает
в очередь повторения и уходит из неё, когда закрыт правильно — в разборе или
при пересдаче урока. Без этого заваленные вопросы исчезали бы вместе с экраном
результата, и обучения бы не было.

**Удаление аккаунта.** Требование 152-ФЗ и обязательное условие App Store для
приложений с регистрацией. Удаляет все связанные данные явно, не полагаясь
на каскады БД. Рядом — выгрузка своих данных одним JSON.

## Баланс

Правится в одном файле — `app/game/economy.py`:

```
MAX_LIVES = 5                  жизней максимум
LIFE_REGEN_SECONDS = 30 * 60   +1 жизнь каждые 30 минут
XP_PER_CORRECT = 4             опыт за верный ответ
XP_LESSON_BONUS = 15           за прохождение урока
XP_PERFECT_BONUS = 10          за урок без ошибок
XP_REPEAT_MULTIPLIER = 0.3     повтор урока — 30% опыта
XP_PER_REVIEW_CORRECT = 2      опыт за верный ответ в разборе
DEFAULT_DAILY_GOAL_XP = 20     дневная цель по умолчанию
REVIEW_BATCH_SIZE = 12         вопросов в одном разборе
```

## Контент

`seed.py` загружает курс «Водоснабжение» с двумя юнитами и двумя уроками
(включая тот самый урок «Установка насоса» из прототипа — все 5 типов заданий).
Скрипт идемпотентный: повторный запуск обновляет уроки и поднимает `version`,
чтобы клиент понял, что контент надо перекачать.

Свои уроки добавляются туда же, либо потом — через веб-CMS.

```
  game/

    service.py         игровая логика

```

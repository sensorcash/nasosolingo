# Деплой: запуск для людей

Как вывести Насосолинго в интернет, чтобы приложение открывалось с любого
телефона, а не только в твоей Wi-Fi. Плюс настройка почты и аналитики.

Честно: часть шагов делается руками в реальном мире (арендовать сервер, купить
домен, вписать секреты) — это за тебя не сделать. Но всё готово так, чтобы запуск
был по инструкции, а не с нуля.

---

## Что уже готово в коде

- `Dockerfile` — образ приложения для прода
- `docker-compose.prod.yml` — приложение + PostgreSQL + Redis одной командой
- `.env.production.example` — все нужные настройки с подсказками
- Настоящий `/health` — проверяет базу и Redis (для мониторинга)
- Почта через SMTP (реальные письма сброса пароля)
- Аналитика на `/admin` (воронка, сложные вопросы, активность)
- Прод-режим (`APP_ENV=production`) блокирует dev-аккаунт `admin/12345`

---

## Шаг 1. Где хостить (152-ФЗ)

Персональные данные граждан РФ должны храниться в России. Подходят:

| Хостинг | Чем удобен |
|---|---|
| **Timeweb Cloud** | простой, дешёвый, есть готовый Docker |
| **Yandex Cloud** | managed PostgreSQL и Redis, но дороже |
| **VK Cloud** | аналогично Яндексу |
| **Selectel** | гибко, облачные серверы |
| **Reg.ru / Beget** | бюджетно для старта |

Для начала хватит **облачного сервера (VPS)** за ~300–600 ₽/мес: 2 ГБ RAM, Ubuntu 22.04.
Managed-базы можно подключить позже, когда пойдёт нагрузка.

---

## Шаг 2. Домен и DNS

1. Купи домен (Reg.ru, nic.ru) — например `nasosolingo.ru`.
2. В DNS добавь A-запись, указывающую на IP сервера.
3. Дождись, пока домен начнёт открывать сервер (обычно до часа).

---

## Шаг 3. Подготовить сервер

Подключись по SSH и поставь Docker:

```bash
ssh root@IP_СЕРВЕРА
curl -fsSL https://get.docker.com | sh
```

Скопируй проект на сервер (с локального компа):

```bash
scp -r nasosolingo/backend root@IP_СЕРВЕРА:/opt/nasosolingo
```

---

## Шаг 4. Заполнить настройки

На сервере:

```bash
cd /opt/nasosolingo
cp .env.production.example .env
nano .env
```

Заполни обязательное:

```
JWT_SECRET=...        # python3 -c "import secrets; print(secrets.token_urlsafe(48))"
POSTGRES_PASSWORD=... # сильный пароль
PUBLIC_BASE_URL=https://nasosolingo.ru
CORS_ORIGINS=https://nasosolingo.ru
ADMIN_EMAILS=ты@почта.ру     # с этого аккаунта откроется /admin
```

Секрет генерируется командой (выполни и вставь результат):

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

---

## Шаг 5. Почта (сброс пароля)

Без почты приложение работает, но пользователь не восстановит пароль — ссылка
уходит в лог сервера, а не на e-mail. Для реальных людей почту надо настроить.

**Самое простое — Яндекс 360 для бизнеса** (почта на своём домене):

1. Заведи ящик `no-reply@nasosolingo.ru` в Яндекс 360.
2. Создай пароль приложения (Настройки → Безопасность → Пароли приложений).
3. В `.env`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SSL=true
SMTP_USER=no-reply@nasosolingo.ru
SMTP_PASSWORD=пароль_приложения
SMTP_FROM=no-reply@nasosolingo.ru
```

Другие варианты: Mail.ru для бизнеса (smtp.mail.ru), или транзакционные сервисы
Unisender / SendPulse (у них свои SMTP-данные, вписываются так же).

Проверка: запроси сброс пароля в приложении — должно прийти письмо.

---

## Шаг 6. Запуск

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Это соберёт образ, поднимет базу и Redis, применит миграции, загрузит уроки
и запустит сервер. Проверь:

```bash
curl http://localhost:8000/health
# {"status":"ok","checks":{"db":true,"redis":true}}
```

---

## Шаг 7. HTTPS (обязательно)

Без HTTPS пароли идут открытым текстом. Проще всего — Caddy (сам получает
сертификат Let's Encrypt). Создай `Caddyfile`:

```
nasosolingo.ru {
    reverse_proxy localhost:8000
}
```

```bash
docker run -d --network host -v $PWD/Caddyfile:/etc/caddy/Caddyfile \
  -v caddy_data:/data caddy
```

Теперь приложение открывается по `https://nasosolingo.ru/app` с любого телефона.

---

## Шаг 8. Аналитика

Зайди на `https://nasosolingo.ru/app` под аккаунтом, чей e-mail в `ADMIN_EMAILS`,
затем открой `https://nasosolingo.ru/admin`. Увидишь:

- **Обзор** — пользователи, активные за 7 дней, прохождения, опыт
- **Активность по дням** — график занятий
- **Воронка** — докуда доходят по урокам (где бросают)
- **Сложные вопросы** — где чаще всего ошибаются (что переписать)

«Сложные вопросы» — самое ценное: показывает, какие вопросы непонятны или
слишком трудны. По ним правишь контент в `content_water.py`.

---

## Обновление версии

Скопировал новый код на сервер и:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Миграции применятся сами. Данные в базе сохранятся (том `pgdata`).

## Чеклист перед публичным запуском

- [ ] `JWT_SECRET` — случайный, не из примера
- [ ] `POSTGRES_PASSWORD` — сильный
- [ ] `APP_ENV=production` (в compose уже так) — dev-аккаунт заблокирован
- [ ] `CORS_ORIGINS` — только твой домен, не `*`
- [ ] HTTPS работает
- [ ] Почта отправляет письма (проверил сброс пароля)
- [ ] `/health` отвечает `ok`
- [ ] Настроен бэкап базы (например, `pg_dump` по расписанию)
- [ ] Зарегистрирован оператор ПД в Роскомнадзоре, есть политика конфиденциальности

---

## Что дальше, когда запустишь

Дай ссылку пяти монтажникам, пусть пройдут пару уроков. Через день загляни
в `/admin`: увидишь, докуда дошли и на каких вопросах спотыкались. Это и есть
тот сигнал, ради которого всё затевалось — он подскажет, что чинить в первую
очередь, лучше любых догадок.

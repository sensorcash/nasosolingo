# Как добавлять уроки и типы заданий

Две разные задачи, и устроены они по-разному:

- **Добавить урок или уровень** — правка данных в `seed.py`. Программировать не нужно.
- **Добавить новый ТИП задания** — правка кода клиента. Нужен программист.

Ниже про обе.

---

## Часть 1. Структура контента

```
Курс «Водоснабжение»
├── Юнит «Азы»
│   └── Урок «Типы насосов»
├── Юнит «Монтаж скважинного»
│   └── Урок «Установка насоса»
└── Юнит «Разные форматы»
    └── Урок «Разные форматы»
```

- **Курс** — большая тема (водоснабжение, отопление…).
- **Юнит** — раздел внутри курса. На карте это отрезок пути.
- **Урок** — то, что проходят за один заход. Кружок на карте.
- **Вопрос** — один экран внутри урока.

Уроки открываются по порядку: пройден предыдущий — открылся следующий.
Порядок задаёт поле `order`.

---

## Часть 2. Добавить урок

Всё в файле `seed.py`. Открой его, найди готовый урок, скопируй, поменяй.

### Скелет урока

```python
MOJ_UROK = {
    "slug": "pump-cable",          # латиницей, уникально в юните
    "title": "Кабель и защита",    # как показывать
    "order": 2,                    # позиция в юните
    "content": {
        "questions": [
            # ... вопросы, см. часть 4
        ],
    },
}
```

### Подключить урок

Внизу `seed.py`, в функции `main`, добавь строку рядом с другими `upsert_lesson`:

```python
await upsert_lesson(session, units["install"].id, MOJ_UROK)
```

`units["install"]` — в какой юнит класть. Ключи юнитов заданы вверху в списке `UNITS`.

### Применить

```
.venv\Scripts\python seed.py
```

Скрипт умный: повторный запуск не плодит дубли, а обновляет урок и поднимает
его версию (клиент поймёт, что контент изменился). Ошибиться и запустить
дважды — не страшно.

## Часть 3. Добавить юнит или курс

### Новый юнит

Вверху `seed.py` в списке `UNITS`:

```python
UNITS = [
    {"slug": "basics",  "title": "Азы",                "order": 1},
    {"slug": "install", "title": "Монтаж скважинного", "order": 3},
    {"slug": "cable",   "title": "Электрика",          "order": 5},   # новый
]
```

Потом клади в него уроки: `units["cable"].id`.

### Новый курс

Пока в `seed.py` один курс. Второй заводится по образцу словаря `COURSE` —
но это уже требует небольшой правки скрипта. Когда курсов станет много,
это сигнал, что пора делать веб-админку (см. дорожную карту).

## Часть 4. Типы заданий

Сейчас движок умеет **девять** типов. У каждого — свой формат в JSON.
Все поля с объяснениями (`explain_ok`, `explain_err`) необязательны, но
без них человек не поймёт свою ошибку — лучше писать.

### 1. `mc` — выбор варианта

```python
{
    "id": "q1",
    "type": "mc",
    "kicker": "Правило глубины",        # маленький заголовок сверху
    "prompt": "На какой глубине висит насос?",
    "scenario": "Скважина 50 м...",     # необязательный блок с условием
    "options": ["На дне", "Ниже уровня", "У оголовка"],
    "answer": 1,                        # индекс верного (с нуля)
    "explain_ok": "Верно!",
    "explain_err": ["На дне — песок", "", "У оголовка — сухой ход"],
    # explain_err — по одному объяснению на вариант; для верного можно ""
}
```

### 2. `odd` — что лишнее

```python
{
    "id": "q2",
    "type": "odd",
    "kicker": "Что лишнее",
    "prompt": "Что не относится к скважинному насосу?",
    "items": ["Крыльчатка", "Клапан", "Дымоход", "Кабель"],
    "answer": 2,                        # индекс лишнего
    "explain_ok": "Верно, дымоход лишний.",
    "explain_err": "Лишний — дымоход.",
}
```

### 3. `order` — расставь по порядку

```python
{
    "id": "q3",
    "type": "order",
    "kicker": "По порядку",
    "prompt": "Расставь монтаж по шагам.",
    "hint": "Первым — насос.",
    "items": [                          # ПРАВИЛЬНЫЙ порядок; игроку покажем перемешанным
        "Опустить насос",
        "Присоединить клапан",
        "Проложить трубу",
        "Поставить гидробак",
    ],
    "explain_ok": "Точно!",
    "explain_err": "Порядок сверху вниз по списку.",
}
```

### 4. `number` — ввод числа

```python
{
    "id": "q4",
    "type": "number",
    "kicker": "Посчитай напор",
    "prompt": "Уровень 32 м + дом 8 м + 30 м. Сколько метров?",
    "unit": "м",                        # подпись у поля, необязательно
    "answer": 70,                       # правильное число
    "tolerance": 2,                     # допустимое отклонение (по умолчанию 0)
    "hint": "Сложи три числа.",
    "explain_ok": "Верно, 70 м.",
    "explain_err": "32 + 8 + 30 = 70 м.",
    # принимает и точку, и запятую как разделитель
}
```

### 5. `hotspots` — найди на картинке

Универсальная «найди нужное место» для ЛЮБОЙ картинки. Зоны задаются
в процентах от размера картинки — не в пикселях, чтобы работало на любом экране.

```python
{
    "id": "q5",
    "type": "hotspots",
    "kicker": "Найди на схеме",
    "prompt": "Где обратный клапан?",
    "image": "pump-types.jpg",          # файл из web/img/
    "image_alt": "Схема насоса",
    "hint": "Сразу над насосом.",
    "spots": [
        {"x": 25, "y": 78, "r": 9, "label": "насос",  "correct": False},
        {"x": 25, "y": 55, "r": 9, "label": "клапан", "correct": True},
        {"x": 72, "y": 45, "r": 9, "label": "другой", "correct": False},
    ],
    # x, y — центр зоны в % (0–100). r — радиус в % ширины. correct — верная зона.
    "explain_ok": "Да, клапан над насосом.",
    "explain_err": "Клапан — прямо над насосом.",
}
```

Как разметить: открой картинку, прикинь положение на глаз в процентах
(левый верхний угол — 0,0; правый нижний — 100,100). Радиус 8–10 обычно удобен.

### 6. `tap` — найди ошибку на схеме скважины

Рисует ОДНУ встроенную сцену скважины. Зоны фиксированы: `pump`, `level`, `head`.
Для произвольных картинок используй `hotspots` — он гибче.

```python
{
    "id": "q6",
    "type": "tap",
    "kicker": "Найди ошибку",
    "prompt": "Тапни причину, по которой насос сгорит.",
    "answer": "pump",                   # pump | level | head
    "hint": "Смотри на уровень воды.",
    "explain_ok": "Верно, сухой ход.",
    "explain_err": "Насос висит выше уровня воды.",
}
```

### 7. `slider` — повесь насос в зону

Тоже одна встроенная сцена. Настраивается только зелёная зона.

```python
{
    "id": "q7",
    "type": "slider",
    "kicker": "Поставь правильно",
    "prompt": "Опусти насос в рабочую зону.",
    "green_zone": [42, 82],             # диапазон правильного положения, 0–100
    "hint": "В воде, но выше дна.",
    "explain_ok": "Идеально.",
    "explain_low": "Выше уровня — сухой ход.",   # если поднял слишком высоко
    "explain_high": "Достаёт до дна — песок.",   # если опустил слишком низко
}
```

### 8. `sound` — определи по звуку

Проигрывает аудио, игрок выбирает вариант. Файл — из `web/img/audio/`
(короткое имя резолвится в `/static/img/audio/`). Сейчас там заглушки-тоны,
заменяются реальными записями насосов.

```python
{
    "id": "q1",
    "type": "sound",
    "kicker": "Послушай насос",
    "prompt": "Что за неисправность по звуку?",
    "audio": "cavitation.wav",
    "options": ["Кавитация", "Норма", "Обрыв фазы"],
    "answer": 0,
    "explain_ok": "Да, высокий призвук — кавитация.",
    "explain_err": ["", "Звук неровный.", "Обрыв фазы звучит иначе."],
}
```

### 9. `match` — соедини пары

```python
{
    "id": "q8",
    "type": "match",
    "kicker": "Симптом → причина",
    "prompt": "Свяжи неисправность с причиной.",
    "pairs": [
        {"left": "Гудит, не качает", "right": "Сухой ход"},
        {"left": "Песок в воде",     "right": "Висит низко"},
    ],
    "explain_ok": "Связал верно!",
}
```

### Картинка в любом вопросе

К вопросу любого типа можно добавить картинку сверху:

```python
    "image": "shema.jpg",
    "image_alt": "Описание",
    "image_caption": "Подпись",
```

## Часть 5. Добавить СВОЙ тип задания (для программиста)

Это правка клиента `web/index.html`, не `seed.py`. Три шага.

**Шаг 1. Зарегистрировать тип** в диспетчере (одна строка):

```js
({mc: renderMC, tap: renderTap, slider: renderSlider, match: renderMatch,
  odd: renderOdd, order: renderOrder, number: renderNumber, hotspots: renderHotspots,
  myType: renderMyType   // ← добавить сюда
}[q.type] || renderUnknown)(zone, q);
```

**Шаг 2. Написать рендерер.** Каждый устроен одинаково: рисует UI в `zone`
и задаёт глобальную функцию `CHECK`, которая возвращает `{correct, text}`.

```js
function renderMyType(zone, q){
  let sel = null, locked = false;

  // 1. нарисовать задание
  zone.innerHTML = `... разметка из q ...`;

  // 2. повесить обработчики; когда есть ответ — enableCheck(true)
  //    (это включает кнопку «Проверить»)

  // 3. задать проверку
  CHECK = () => {
    locked = true;
    const ok = /* сравнить ответ с q.answer */;
    return {
      correct: ok,
      text: ok ? q.explain_ok : (q.explain_err || 'Не то.'),
    };
  };
}
```

Всё остальное — засчитывание опыта, попадание в разбор ошибок, экран
результата — движок берёт на себя. Рендереру нужно только вернуть
`{correct, text}`.

**Шаг 3. Добавить стили** рядом с остальными в блоке `<style>` и завести
пример в `seed.py`.

Хорошие образцы для копирования: `renderOdd` (простой, на кнопках),
`renderNumber` (с полем ввода), `renderHotspots` (с картинкой и зонами).

### Идеи типов под насосную тематику

- **Ползунки-параметры:** задать напор и расход, попасть в рабочую точку.
- **Звук:** уже есть тип `sound` (заглушки-тоны). Осталось записать реальные
  звуки насосов и, при желании, автоматическое распознавание (это уже ML).
- **Сборка:** перетащить узлы обвязки в правильные места на схеме.
- **Таймер:** видео монтажа, поставить на паузу в момент ошибки.

Первые два реалистичны на вебе уже сейчас. «Перетаскивание» на телефоне
капризно — лучше делать через тап-по-очереди, как в `match`.

## Шпаргалка

| Хочу | Где | Нужен программист |
|---|---|---|
| Новый урок | `seed.py` → `upsert_lesson` | нет |
| Новый юнит | `seed.py` → список `UNITS` | нет |
| Поменять вопрос | `seed.py` | нет |
| Картинку в вопрос | поле `image` + файл в `web/img/` | нет |
| Новый ТИП задания | `web/index.html` → рендерер | да |

После правки `seed.py` — всегда `python seed.py`. После правки клиента —
`Ctrl+Shift+R` в браузере.

Основной контент лежит отдельно от служебного кода — в файле `content_water.py`.
Это 30 уроков в 6 юнитах:

| Юнит | О чём | Уроков |
|---|---|---|
| Как работает насос | устройство и принцип | 5 |
| Характеристики и подбор | напор, расход, кривая, TDH, дебит | 5 |
| Монтаж в скважину | глубина, кабель, трос, клапан, оголовок | 5 |

Правится ровно как описано выше — это обычные данные. После правки:
`python seed.py`. Целостность контента проверяется тестами
(`tests/test_content_water.py`) — если что-то забыл, тест подскажет.

### Картинки уроков — заглушки

Сейчас у каждого урока картинка-заглушка из `web/img/water/` с подписью,
что на ней должно быть. Имя файла = slug урока.

**Заменить:** положи свою картинку с тем же именем. Для обычных иллюстраций
координаты не важны. Уроки с «горячими точками» (найди на схеме) используют
`pump-types.jpg` — при замене этой схемы проверь координаты точек в контенте.

Перегенерировать заглушки: `python tools/make_placeholders.py`.

## Гифки и анимации

**GIF в уроке.** Поддерживаются как обычная картинка — просто укажи `.gif`
в поле `image`:

```python
"image": "water/anim-flow.gif",
"image_caption": "Работа насоса",
```

Файл кладётся в `web/img/water/`. Сейчас там анимированная заглушка
`anim-flow.gif` (её видно в первом уроке) — замени своей анимацией.
Поддерживаются GIF, а также PNG/JPG/SVG/WebP.

**Встроенные анимации** (готовы, ничего делать не нужно): конфетти на идеальном
уроке и при получении ачивки, счётчик опыта, пульс текущего урока на карте,
пузырьки в водоносном слое, всплытие значков достижений.

**Звук.** Короткие эффекты (верно/неверно/уровень пройден/ачивка) синтезируются
в браузере — файлов нет, работает офлайн. Отключается кнопкой в профиле
(настройка запоминается). Реальные звуки насосов для заданий типа `sound`
лежат отдельно в `web/img/audio/`.

## Маскот и схема скважины (теперь картинки)

**Маскот** — 4 файла в `web/img/mascot/`: `happy.png`, `neutral.png`, `worried.png`,
`party.png` (прозрачный PNG). Меняются подстановкой файла. Хочешь одного маскота без
настроений — впиши один и тот же файл во всех строках `const MASCOT` в `index.html`.

**Схема скважины** (в заданиях «найди ошибку» и «поставь глубину») — 2 файла в `web/img/well/`:
`bg.jpg` (фон: грунт, вода, колонна, оголовок — БЕЗ насоса) и `pump.png` (насос отдельно,
прозрачный PNG, он двигается и подсвечивается). Меняются подстановкой файлов.

Позиции кликабельных зон и ход насоса заданы в процентах в объекте `const WELL` в
`index.html`. Если заменишь фон и объекты съедут — поправь проценты там (`headY`, `levelY`,
`pumpTapY`, `sliderMin`, `sliderMax`, `pumpW`).

# Как запустить бэкенд — пошагово, с нуля

Гайд для того, кто раньше не поднимал серверные приложения. Ничего не нужно знать заранее.
Команды даны для **Windows** (основной вариант), внизу каждого шага — версия для Mac/Linux.

Времени: примерно 30–40 минут в первый раз, из них большая часть — установка Docker.

---

## Что мы вообще собираемся сделать

У тебя на компьютере поднимутся **три вещи**:

1. **PostgreSQL** — база данных. Здесь будут храниться пользователи и их прогресс.
2. **Redis** — быстрое временное хранилище. Считает попытки входа, хранит ссылки сброса пароля.
3. **Наше приложение** (Python) — оно принимает запросы «зарегистрируй», «впусти», «дай профиль».

Первые два запустятся через Docker (одной командой, ничего настраивать не надо).
Третье запустится через Python.

В конце ты откроешь в браузере страницу, где можно **потыкать кнопками** и увидеть, как регистрируется пользователь. Это и есть цель.

> Важно понимать: это **бэкенд**, у него нет красивого экрана. Это «двигатель без кузова».
> Красивая часть (та игра-прототип) будет приложением на iPhone, и она потом будет обращаться к этому двигателю.

---

## Шаг 0. Установить две программы

### 0.1 Python

Скачай с [python.org](https://www.python.org/downloads/) версию **3.11 или новее**.

При установке на Windows **обязательно поставь галочку «Add python.exe to PATH»** на первом экране установщика. Если забыть — команды `python` не будут работать, и придётся переустанавливать.

Проверка (см. шаг 2, как открыть терминал):
```
python --version
```
Должно вывести что-то вроде `Python 3.12.x`.

### 0.2 Docker Desktop

Скачай с [docker.com](https://www.docker.com/products/docker-desktop/) и установи.

Docker — это программа, которая умеет запускать готовые «коробочки» с уже настроенными
приложениями. Нам нужны коробочки с PostgreSQL и Redis. Без Docker их пришлось бы
устанавливать и настраивать руками — это долго и мучительно, особенно Redis на Windows.

**На Windows Docker требует WSL2.** Обычно установщик всё делает сам и просит перезагрузиться.
Если ругается на виртуализацию — её нужно включить в BIOS (пункт называется Virtualization,
VT-x или AMD-V). Это самое неприятное место всей установки, дальше будет легко.

После установки **запусти Docker Desktop** и дождись, пока в левом нижнем углу
индикатор станет зелёным («Engine running»). Docker должен быть запущен всё время,
пока ты работаешь с проектом.

## Шаг 1. Распаковать проект

Распакуй архив `nasosolingo-auth.zip` в удобное место, например:

```
C:\projects\nasosolingo-auth
```

Внутри должны быть папка `app`, файл `docker-compose.yml`, `requirements.txt` и другие.

> Совет: не клади в папку с русскими буквами и пробелами в пути (типа `C:\Мои документы\`).
> Иногда это создаёт проблемы. `C:\projects\` — безопасно.

---

## Шаг 2. Открыть терминал в этой папке

Терминал (командная строка) — это окно, куда печатают команды.

**Самый простой способ на Windows:** открой папку проекта в проводнике,
кликни в адресную строку сверху, напечатай `powershell` и нажми Enter.
Откроется чёрное окно, уже находящееся в нужной папке.

Проверь, что ты в правильном месте — набери:
```
dir
```
Должен увидеть список файлов проекта (`app`, `requirements.txt`, `docker-compose.yml`…).
Если видишь что-то другое — ты не в той папке.

> **Mac:** правый клик на папке → «Новый терминал по адресу папки». Проверка — команда `ls`.

**Все команды дальше выполняются в этом окне.**

---

## Шаг 3. Запустить базы данных

Убедись, что Docker Desktop запущен (зелёный индикатор). Затем:

```
docker compose up -d
```

Первый раз это займёт 1–3 минуты — Docker скачивает PostgreSQL и Redis из интернета.
Увидишь строки про «Pulling», потом «Started».

Проверить, что всё поднялось:
```
docker compose ps
```
Должны быть **две** строки — postgres и redis — со статусом `running` или `Up`.

> Что произошло: у тебя теперь работают база данных и Redis. Они будут работать в фоне,
> даже если закрыть терминал. Останавливать их — командой `docker compose down` (см. в конце).

---

## Шаг 4. Создать виртуальное окружение

```
python -m venv .venv
```

Команда создаст папку `.venv` внутри проекта. Это «личная аптечка» проекта:
все библиотеки поставятся туда, а не в систему. Так проекты не конфликтуют между собой.

Ничего не выведется — это нормально. Просто появится папка.

---

## Шаг 5. Установить библиотеки

```
.venv\Scripts\python -m pip install -r requirements.txt
```

Займёт 1–2 минуты, побегут строки про Downloading/Installing. В конце — `Successfully installed ...`.

> **Mac/Linux:** `.venv/bin/python -m pip install -r requirements.txt`

Здесь мы намеренно **не «активируем» окружение**, а сразу пишем полный путь
`.venv\Scripts\python`. Так надёжнее: на Windows активация часто спотыкается о политику
безопасности PowerShell. Если хочется активировать — см. раздел «Типичные ошибки».

---

## Шаг 6. Создать файл настроек

```
copy .env.example .env
```

> **Mac/Linux:** `cp .env.example .env`

Файл `.env` хранит настройки: адрес базы, пароли, секретный ключ. В нём уже всё
заполнено значениями для локальной работы — менять ничего не нужно.

> На будущее: когда дойдёт до настоящего сервера, `JWT_SECRET` в этом файле надо будет
> заменить на длинную случайную строку. Локально — не важно.

---

## Шаг 7. Создать таблицы в базе

```
.venv\Scripts\python -m alembic upgrade head
```

База данных сейчас пустая — в ней нет ни одной таблицы. Эта команда создаёт их
(пользователи, устройства, токены). Такие «инструкции по изменению базы» называются
**миграциями**: они хранятся в проекте, и любой человек одной командой получит
точно такую же структуру базы.

Должно закончиться строкой вида `Running upgrade -> 0001, initial auth schema`.

---

## Шаг 8. Запустить приложение

```
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Увидишь примерно такое:

```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.
```

**Готово, сервер работает.**

⚠️ **Это окно надо оставить открытым.** Пока оно открыто — приложение живёт.
Закроешь окно или нажмёшь Ctrl+C — приложение выключится.
Все сообщения (в том числе ссылка для сброса пароля) будут появляться именно здесь.

---

## Шаг 9. Проверить, что всё работает

Открой в браузере:

```
http://localhost:8000/docs
```

Ты увидишь страницу **Swagger** — автоматическую панель со списком всех команд,
которые понимает твой сервер. Это не сайт игры, это «пульт управления двигателем»
для разработчика. Здесь можно нажимать кнопки и смотреть, что отвечает сервер.

### 9.1 Зарегистрировать первого пользователя

1. Найди строку **POST `/api/v1/auth/register`**, кликни по ней — она раскроется.
2. Справа нажми кнопку **«Try it out»**.
3. В поле появится текст-заготовка. Замени его на:

```json
{
  "email": "master@example.ru",
  "password": "nasos-parol-1"
}
```

4. Нажми большую синюю кнопку **«Execute»**.

Ниже, в блоке **Server response**, должен появиться код **201** и ответ примерно такой:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "9tX2f...",
  "token_type": "bearer",
  "user": {
    "id": "6f1c...",
    "email": "master@example.ru",
    "nickname": null,
    "email_verified": false
  }
}
```

**Это успех.** В базе появился первый пользователь, пароль зашифрован, а тебе выдали
два «пропуска» (токена).

- `access_token` — короткий пропуск (15 минут), с ним ходят за данными.
- `refresh_token` — долгий (60 дней), по нему получают новый короткий, когда тот истёк.

**Скопируй `access_token`** целиком (длинная строка) — сейчас пригодится.

### 9.2 Посмотреть профиль

1. Найди **GET `/api/v1/auth/me`**, раскрой, нажми **«Try it out»**.
2. Увидишь поле с названием **`authorization`**. Впиши туда:

```
Bearer ВСТАВЬ_СЮДА_ACCESS_TOKEN
```

Слово `Bearer`, пробел, потом токен. Например: `Bearer eyJhbGciOiJIUzI1NiIs...`

3. **«Execute»**.

Ответ (код 200):
```json
{
  "user": { "email": "master@example.ru", ... },
  "state": { "xp": 0, "level": 1, "lives": 5, "streak_count": 0 }
}
```

Вот оно, игровое состояние: 0 опыта, 1 уровень, 5 жизней. Именно это приложение
на iPhone будет показывать на экране профиля.

> Обрати внимание: обычной кнопки «Authorize» вверху страницы здесь нет — токен
> вставляется прямо в поле `authorization` у конкретной команды. Так и задумано.

### 9.3 Проверить вход

**POST `/api/v1/auth/login`** → «Try it out» → тот же JSON, что при регистрации → «Execute».
Код **200** и новая пара токенов — значит, пароль проверяется правильно.

А теперь **введи пароль неправильно** и выполни ещё раз. Должен прийти код **401**
и текст «Неверный e-mail или пароль». Повтори с неверным паролем 5 раз подряд —
и получишь код **423**: аккаунт временно заблокирован. Это работает защита от подбора пароля.

> Разблокируется сам через минуту. Или сразу — если перезапустить Redis:
> `docker compose restart redis`

### 9.4 Посмотреть на сброс пароля

**POST `/api/v1/auth/password/reset-request`** → `{"email": "master@example.ru"}` → «Execute».

Ответ будет нейтральным: «Если адрес зарегистрирован, мы отправили письмо».
Так и должно быть — сервер намеренно не говорит, есть такой e-mail или нет,
чтобы через эту форму нельзя было проверять чужие адреса.

А теперь **посмотри в чёрное окно терминала**, где работает uvicorn. Там появится строка:

```
WARNING [email] [EMAIL STUB] Сброс пароля для master@example.ru -> https://app.example/reset?token=abc123...
```

Настоящих писем пока нет — вместо отправки ссылка печатается в консоль. Когда подключим
сервис рассылки (Unisender, SendPulse или свой SMTP), эта же ссылка будет уходить письмом.
Меняется это в одном файле — `app/email.py`.

## Как выключать и включать заново

**Выключить всё:**
1. В окне с uvicorn нажми `Ctrl+C`.
2. Затем: `docker compose down` (базы остановятся, данные сохранятся).

**Включить снова** (все шаги установки уже не нужны, только эти два):
```
docker compose up -d
.venv\Scripts\python -m uvicorn app.main:app --reload
```

**Стереть все данные и начать с чистой базы:**
```
docker compose down -v
docker compose up -d
.venv\Scripts\python -m alembic upgrade head
```
(`-v` удаляет и сохранённые данные тоже)

## Типичные ошибки и что делать

| Что видишь | Что это значит | Решение |
|---|---|---|
| `python не является внутренней или внешней командой` | Python не в PATH | Переустановить Python с галочкой «Add python.exe to PATH» |
| `docker: command not found` / `Cannot connect to the Docker daemon` | Docker Desktop не запущен | Запустить Docker Desktop, дождаться зелёного индикатора |
| `port is already allocated` (5432 или 6379) | Порт занят — обычно уже установленным PostgreSQL | Остановить свой PostgreSQL в «Службах» Windows, либо поменять порт в `docker-compose.yml` (`"5433:5432"`) и в `.env` |
| `Address already in use` на 8000 | Приложение уже запущено в другом окне | Закрыть то окно, или запустить на другом порту: добавить `--port 8001` |
| `Connection refused` при регистрации | Docker-контейнеры не поднялись | `docker compose ps` — проверить, что оба `running` |
| `ModuleNotFoundError: No module named 'fastapi'` | Запускаешь системным python, а не из `.venv` | Писать полный путь: `.venv\Scripts\python -m uvicorn ...` |
| `выполнение сценариев отключено в этой системе` | PowerShell блокирует активацию venv | Не активируй venv вообще — используй полный путь `.venv\Scripts\python`. Или разово: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| `Target database is not up to date` | Не выполнены миграции | `.venv\Scripts\python -m alembic upgrade head` |
| Код **409** при регистрации | Такой e-mail уже зарегистрирован | Это правильное поведение — возьми другой e-mail |
| Код **422** в Swagger | Ошибка в JSON (лишняя запятая, кавычки) | Проверь текст запроса посимвольно |

## Полная шпаргалка (все команды подряд)

Первый раз:
```
docker compose up -d
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python -m alembic upgrade head
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Каждый следующий раз:
```
docker compose up -d
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Открыть: **http://localhost:8000/docs**

## Что дальше

Когда это заработает, у тебя есть подтверждение, что фундамент живой:
пользователи регистрируются, пароли защищены, состояние игры хранится.

Следующий кирпич — **игровое ядро**: уроки в виде данных (JSON), сохранение прогресса,
начисление опыта, жизней и «потока». После него бэкенд сможет обслуживать
настоящее приложение, а не только логин.

Отдельно, когда дойдёт до реальных писем: нужен будет аккаунт у сервиса рассылки.
До тех пор ссылки в консоли — вполне рабочий способ тестировать.

# Часть 2. Подключаем игровое ядро

У тебя уже работает первая часть (регистрация и вход). Теперь добавляем саму игру:
уроки, опыт, жизни, поток.

Времени: 10 минут.

---

## Шаг 1. Заменить файлы проекта

1. **Останови сервер:** в окне, где работает uvicorn, нажми `Ctrl+C`.
2. Распакуй новый архив `nasosolingo-backend.zip` **поверх старой папки**, согласившись
   на замену файлов.

> Базу данных трогать не надо — всё, что ты уже создал, останется. Новый код с ней совместим.

---

## Шаг 2. Открыть терминал в папке проекта

Как в прошлый раз: открой папку в проводнике, напечатай в адресной строке `powershell`, Enter.

---

## Шаг 3. Поднять базы (если выключал компьютер)

```
docker compose up -d
```

Если Docker Desktop не запущен — сначала запусти его и дождись зелёного индикатора.

---

## Шаг 4. Добавить новые таблицы

```
.venv\Scripts\python -m alembic upgrade head
```

Появятся таблицы для курсов, уроков и прогресса. Старые данные не пострадают —
миграции только добавляют новое.

Должно закончиться строкой про `0002, game core`.

---

## Шаг 5. Загрузить уроки в базу

```
.venv\Scripts\python seed.py
```

Увидишь:
```
+ курс «Водоснабжение»
+ юнит «Азы»
+ юнит «Монтаж скважинного»
  + урок «Типы насосов» (2 вопросов)
  + урок «Установка насоса» (5 вопросов)

Готово. Контент загружен в базу.
```

**Это ключевой момент всей затеи.** Уроки теперь лежат в базе как данные, а не зашиты
в приложение. Чтобы добавить новый урок или поправить вопрос, не нужно выпускать
обновление в App Store и ждать модерацию — достаточно изменить данные.

Скрипт можно запускать сколько угодно раз: он не создаёт дубли, а обновляет уроки.

---

## Шаг 6. Запустить сервер

```
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Оставь это окно открытым, как и раньше.

---

## Шаг 7. Посмотреть игру в деле

Открой **http://localhost:8000/docs** — теперь там появился второй раздел, **game**.

### 7.1 Войти и взять токен

Раздел **auth** → **POST `/api/v1/auth/login`** → «Try it out» → введи свои e-mail и пароль
(те, что использовал в первой части) → «Execute».

**Скопируй `access_token`** из ответа.

> Токен живёт 15 минут. Если начнёт отвечать 401 — просто войди заново и возьми новый.

Дальше во **все** игровые команды в поле `authorization` вставляешь:
```
Bearer СЮДА_ТОКЕН
```

### 7.2 Карта пути

**GET `/api/v1/game/courses`** → вставь токен в `authorization` → «Execute».

Получишь дерево курса. Обрати внимание на `status` у уроков:

```json
"lessons": [
  { "title": "Типы насосов", "status": "available", ... },
  { "title": "Установка насоса", "status": "locked", ... }
]
```

Первый урок открыт, следующий закрыт — ровно как кружочки на карте в прототипе.
Именно эти данные приложение на iPhone будет рисовать как путь вниз по скважине.

### 7.3 Посмотреть содержимое урока

Скопируй `id` первого урока из предыдущего ответа.

**GET `/api/v1/game/lessons/{lesson_id}`** → вставь `id` и токен → «Execute».

Увидишь тот самый JSON с вопросами, вариантами ответов и объяснениями. Приложение
скачает это один раз и сохранит у себя — поэтому урок можно будет проходить без интернета,
где-нибудь на объекте без связи.

### 7.4 Пройти урок

**POST `/api/v1/game/lessons/{lesson_id}/complete`** → тот же `id` и токен, а в тело:

```json
{
  "client_event_id": "test-001",
  "correct": 2,
  "total": 2,
  "mistakes": 0
}
```

«Execute». Ответ:

```json
{
  "xp_awarded": 33,
  "duplicate": false,
  "state": { "xp": 33, "level": 1, "lives": 5, "streak_count": 1, ... }
}
```

Получил опыт, поток стартовал (`streak_count: 1`).

### 7.5 Проверить защиту от двойного начисления

**Нажми «Execute» ещё раз, ничего не меняя.**

```json
{ "xp_awarded": 33, "duplicate": true, "state": { "xp": 33, ... } }
```

Опыт **не удвоился**, а поле `duplicate` стало `true`. Это и есть та самая идемпотентность:
если у монтажника в поле пропала связь и приложение отправило результат дважды —
опыт начислится ровно один раз.

### 7.6 Проверить, что урок разблокировал следующий

**GET `/api/v1/game/courses`** ещё раз. Теперь:
```
"Типы насосов"      → "done"
"Установка насоса"  → "available"
```

Путь открылся дальше.

### 7.7 Потерять жизни

Пройди урок с ошибками — новый `client_event_id` (например `test-002`) и:

```json
{
  "client_event_id": "test-002",
  "correct": 1,
  "total": 2,
  "mistakes": 2
}
```

В ответе `lives` станет `3`, а `seconds_to_next_life` покажет, сколько секунд
до восстановления следующей капли (30 минут). Жизни восстанавливаются сами по времени —
проверять можно через **GET `/api/v1/game/state`**.

## Шаг 8 (по желанию). Прогнать тесты

Хочешь убедиться, что всё цело — без всякого тыканья кнопками:

```
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q
```

Должно вывести `57 passed`. Тестам не нужны ни Docker, ни база — они поднимают
приложение во временной памяти. Это удобно: после любой правки кода одна команда
показывает, не сломалось ли что-нибудь.

## Как поменять баланс игры

Открой файл `app/game/economy.py`, там сверху:

```python
MAX_LIVES = 5                  # жизней максимум
LIFE_REGEN_SECONDS = 30 * 60   # +1 жизнь каждые 30 минут
XP_PER_CORRECT = 4             # опыт за верный ответ
XP_LESSON_BONUS = 15           # за прохождение урока
XP_PERFECT_BONUS = 10          # за урок без ошибок
XP_REPEAT_MULTIPLIER = 0.3     # повтор урока — 30% опыта
```

Меняешь число, сохраняешь — сервер сам перезапустится (он в режиме `--reload`).

## Как добавить свой урок

Открой `seed.py`, скопируй блок урока, поменяй вопросы, запусти:

```
.venv\Scripts\python seed.py
```

Всё. Никаких релизов, никакой модерации App Store — просто данные в базе.

Поддерживаемые типы заданий (те же, что в прототипе):
- `mc` — выбор одного варианта
- `tap` — найди ошибку на схеме
- `slider` — поставь ползунок в правильную зону
- `match` — свяжи симптом с причиной

---

## Если что-то пошло не так

| Что видишь | Решение |
|---|---|
| `Target database is not up to date` | `.venv\Scripts\python -m alembic upgrade head` |
| 401 на игровых командах | Токен протух (15 мин) — войди заново, возьми новый |
| Пустой список в `/courses` | Не запущен `seed.py` |
| `Can't locate revision 0002` | Файлы распакованы не полностью — распакуй архив заново |
| 400 `invalid_result` | В `total` указано не то число вопросов, что в уроке |

## Что теперь есть

Бэкенд умеет всё, что нужно настоящей игре:

- пользователи, вход, безопасные пароли;
- уроки как данные — новый контент без релиза приложения;
- прогресс, разблокировка уроков по цепочке;
- опыт, уровни, жизни с восстановлением по времени, поток по дням;
- безопасная офлайн-синхронизация.

Следующий большой шаг — **приложение на Flutter**: экран карты-скважины, движок уроков,
локальный кэш контента и очередь событий для офлайна. То есть прототип, который ты
уже видел, но подключённый к этому бэкенду и собранный под iPhone.

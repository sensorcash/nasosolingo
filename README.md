# Насосолинго — передача проекта

Обучающее мобильное приложение для монтажников насосного оборудования.
Механика в духе Duolingo, предметная область — водоснабжение и скважинные насосы.
Заказчик: Aquario. Рынок: Россия.

**Статус: рабочий прототип с полноценным бэкендом.** Есть сервер, база, веб-клиент
и 95 тестов. Нет: нативных приложений, офлайн-режима, пушей, админки контента.

## 2. Быстрый старт

Нужны Docker и Python 3.11+.

```bash
cd backend
docker compose up -d                       # PostgreSQL + Redis
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
python seed.py                             # контент уроков
python seed_dev.py                         # dev-аккаунт (только APP_ENV=dev)
uvicorn app.main:app --reload --host 0.0.0.0
```

- Приложение: http://localhost:8000/app (вход `admin` / `12345`)
- Swagger: http://localhost:8000/docs
- С телефона в той же сети: `http://<IP>:8000/app`

Тесты (БД не нужна — SQLite в памяти + fakeredis):

```bash
pip install -r requirements-dev.txt
pytest -q          # ожидается: 66 passed
```

## 3. Что работает

**Авторизация.** Регистрация и вход по e-mail либо короткому логину. Argon2id,
access-JWT (15 мин) + непрозрачный refresh (60 дней) с ротацией и детекцией
повторного использования. Rate limiting и экспоненциальный локаут на Redis.
Сброс пароля по одноразовой ссылке. Мягкая верификация e-mail.

**Игровое ядро.** Курсы → юниты → уроки. Контент урока — JSON в БД. Прогресс
с разблокировкой по цепочке. Опыт, уровни, жизни с регенерацией по времени,
поток (streak) по местной дате игрока. Идемпотентная отправка результатов
и пакетная синхронизация офлайн-очереди.

**Клиент.** Один HTML-файл, раздаётся тем же сервером с `/app`. Вход, карта-скважина,
четыре типа заданий (`mc`, `tap`, `slider`, `match`), разбор ошибок, экран результата,
автообновление токена. Работает в Safari на iPhone, добавляется на домашний экран.

**Разбор ошибок.** Результат по каждому вопросу сохраняется. Заваленные вопросы
попадают в очередь повторения и уходят из неё, когда закрыты правильно.
Отдельный режим тренировки на своих ошибках.

**Дневная цель.** Настраиваемая цель по опыту (10/20/40/70), прогресс за день,
сброс по местной дате игрока.

**Удаление аккаунта и выгрузка данных.** Требование 152-ФЗ и обязательное
условие публикации в App Store.

**Контент.** Курс «Водоснабжение», два юнита, два урока (7 вопросов, все четыре типа).

| Не сделано | Комментарий |

| Продакшен-развёртывание | Только локальный запуск |

## 5. Технологии и почему они

| Слой | Выбор | Причина |
|---|---|---|
| Бэкенд | FastAPI (Python) | Стек заказчика, быстрая разработка |
| БД | PostgreSQL | Основное хранилище, включая ПД |
| Кэш | Redis | Rate limiting, токены сброса, позже лидерборды |
| Миграции | Alembic | 3 миграции, применяются с нуля |
| Пароли | Argon2id (`argon2-cffi`) | Рекомендация OWASP |
| Клиент (сейчас) | Ванильный HTML/JS | Ноль сборки, открывается везде |
| Клиент (план) | Flutter | Один код на iOS и Android |
| Тесты | pytest + SQLite + fakeredis | Без внешних зависимостей |

Архитектура — **модульный монолит**, не микросервисы. Обоснование в `docs/03-decisions.md`.

## 7. API

Все игровые эндпоинты требуют `Authorization: Bearer <access_token>`.

**auth** — `POST /api/v1/auth/{register,login,refresh,logout}`,
`POST /api/v1/auth/password/{reset-request,reset-confirm}`,
`GET /api/v1/auth/{verify-email,me}`, `GET /api/v1/auth/me/export`,
`DELETE /api/v1/auth/me`

**game** — `GET /api/v1/game/state`, `GET /api/v1/game/courses`,
`GET /api/v1/game/lessons/{id}`, `POST /api/v1/game/lessons/{id}/complete`,
`POST /api/v1/game/sync`, `GET /api/v1/game/review`,
`POST /api/v1/game/review/complete`, `PUT /api/v1/game/daily-goal`

Полные схемы запросов и ответов — в Swagger на `/docs`, детали ошибок — в `docs/02-auth-spec.md`.

## 8. Формат контента урока

Уроки — данные, а не код. Структура `lessons.content`:

```json
{
  "questions": [
    { "id": "q1", "type": "mc", "kicker": "Правило глубины",
      "prompt": "На какой глубине...", "scenario": "необязательно",
      "options": ["...", "...", "..."], "answer": 1,
      "explain_ok": "...", "explain_err": ["...", "", "..."] },

    { "id": "q2", "type": "tap", "prompt": "...", "scene": "dryrun",
      "answer": "pump", "hint": "...",
      "explain_ok": "...", "explain_err": "..." },

    { "id": "q3", "type": "slider", "prompt": "...", "green_zone": [42, 82],
      "explain_ok": "...", "explain_low": "...", "explain_high": "..." },

    { "id": "q4", "type": "match", "prompt": "...",
      "pairs": [{ "left": "симптом", "right": "причина" }],
      "explain_ok": "..." }
  ]
}
```

Ограничения текущего клиента:
- `tap` рисует одну зашитую сцену; допустимые значения `answer`: `pump`, `level`, `head`.
  Новые сцены требуют правки клиента.
- `slider` — одна сцена скважины, настраивается только `green_zone`.
- `mc`: длина `explain_err` должна совпадать с длиной `options`.

Добавление урока: правка `seed.py` → `python seed.py`. Скрипт идемпотентный,
повышает `version` урока, чтобы клиент понял, что контент обновился.

## 9. Тесты

95 тестов, ~5 секунд, внешних зависимостей нет.

```
tests/test_economy.py     23  чистая логика: жизни, поток, опыт, уровни
tests/test_auth_api.py    17  регистрация, вход, ротация токенов, сброс пароля
tests/test_game_api.py    17  прогресс, разблокировка, идемпотентность, синхронизация
tests/test_dev_login.py    9  вход по логину, защита dev-аккаунта
tests/test_new_features.py 29 разбор ошибок, дневная цель, удаление аккаунта
```

`conftest.py` подменяет PostgreSQL на SQLite в памяти и Redis на fakeredis.
Логика приложения при этом настоящая — тесты идут через реальные HTTP-запросы.

Модели используют `sa.Uuid` (не `postgresql.UUID`) именно ради переносимости
тестов на SQLite. В PostgreSQL это тот же нативный тип `UUID`.

## 10. Известные ограничения и грабли

**Даты и часовые пояса.** SQLite отдаёт наивные datetime, PostgreSQL — с поясом.
В коде есть хелперы `_aware()`; при добавлении сравнений дат их надо использовать,
иначе тесты упадут с `TypeError`.

**Значения по умолчанию.** `server_default` срабатывает при вставке в БД, а не при
создании Python-объекта. Новые строки, с полями которых работают до `flush()`,
надо инициализировать явно (см. `UserProgress` в `game/service.py`).

**Правильные ответы уходят на клиент** вместе с уроком — иначе не сыграть офлайн.
Осознанный размен: опыт ни во что реальное не конвертируется. **Если появится
сертификат, дающий скидку, экзамен обязан проверяться только на сервере.**

**CORS открыт настежь** (`allow_origins=["*"]`) для удобства разработки.
Перед продакшеном сузить.

**dev-аккаунт.** `seed_dev.py` создаёт `admin`/`12345` в обход политики паролей
и отказывается работать, если `APP_ENV != dev`. Защиту не снимать.

**JWT-секрет** в `.env.example` — плейсхолдер. В продакшене заменить на случайный.

## 12. Контекст, который стоит знать

Проект для российского рынка, и это влияет на решения сильнее, чем обычно:

- **Персональные данные** граждан РФ обязаны храниться в России (152-ФЗ).
- **Публикация в App Store** для российского разработчика затруднена: карты
  российских банков Apple не принимает, монетизация недоступна. Оплата Apple
  Developer решается через зарубежную карту или посредников.
- **Google Play** не платит российским разработчикам; для Android основной
  канал — **RuStore**, где ИП может публиковаться.
- **FCM ненадёжен** на российских Android-устройствах — для пушей нужен RuStore Push.
- Аудитория (монтажники, преимущественно мужчины, регионы) смещена в сторону
  Android сильнее, чем население в среднем. Ставка «сначала iOS» сделана
  заказчиком по личным причинам, её стоит перепроверить.

Подробнее — `docs/01-architecture.md`, раздел «Российская специфика».
